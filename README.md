# 시방서 AI 분석 시스템

포스코 사내 시방서의 각 조항을 최신 국가건설기준센터 KCS와 비교하고, 담당자가 `남김`, `삭제`, `보류`를 결정하는 웹 도구입니다. 로컬 실행 시 원본 문서와 판단 결과는 이 PC에 저장되고, 상시 운영 시에는 백엔드의 영구 볼륨에 저장됩니다. OpenAI 기능을 켠 경우에만 비교 대상 문장이 OpenAI API로 전송됩니다.

## 바로 실행

VS Code에서 이 폴더를 열고 터미널에서 실행합니다.

```powershell
npm run local
```

브라우저에서 <http://localhost:3000>을 엽니다. 분석 API는 <http://127.0.0.1:8000>에서 동작합니다. 실행을 끝낼 때는 터미널에서 `Ctrl+C`를 누릅니다.

현재 작업 폴더에는 필요한 패키지가 설치되어 있습니다. 다른 PC에 복사해 처음 구성할 때만 다음을 실행합니다.

```powershell
npm install
python -m venv .venv
npm run setup:python
Copy-Item .env.example .env
```

## 환경 설정

기본 KCS 자료 폴더는 다음과 같습니다.

```text
C:\Users\00byr\OneDrive\Desktop\260819\kcs downloads
```

앱은 프로젝트의 `.env`를 먼저 읽고, 없으면 KCS 자료 폴더의 상위 폴더와 기존 `C:\Users\00byr\OneDrive\Desktop\260819\spec-matcher\.env`도 확인합니다. 국가건설기준센터 인증키 변수명은 `KCSC_API_KEY`입니다. 인증키는 화면이나 결과 파일로 보내지 않고 서버에서 KCS 갱신 요청에만 사용합니다.

필요하면 `.env.example`을 `.env`로 복사한 뒤 경로를 조정합니다.

GPT 임베딩 재정렬과 후보별 정밀판정을 사용하려면 프로젝트 `.env`에 별도 OpenAI API 키를 설정합니다. ChatGPT 또는 Codex 로그인과 API 키는 서로 다른 인증입니다.

```text
OPENAI_API_KEY=...
OPENAI_EMBEDDING_MODEL=text-embedding-3-small
OPENAI_EMBEDDING_DIMENSIONS=256
OPENAI_RERANK_MODEL=gpt-5.4-mini
```

엄격 임베딩 분석은 키가 없거나 API 호출에 실패하면 중단하고 재시도를 안내합니다. 로컬 검색 결과와 GPT 상세비교 완료 상태는 구분되며, 화면과 로그에는 API 키를 표시하지 않습니다.

### 자동 GPT 상세비교

OpenAI 연결 시 새 업로드와 KCS 재매칭 뒤에는 문서 전체의 본문·표에 GPT 요구사항 상세비교가 자동으로 이어집니다. 기존 문서도 검토 화면을 열면 미완료 구간을 자동 분석합니다. 목차·구조 제목은 문맥으로만 사용합니다. 후보가 없는 본문도 GPT가 원문 요구사항을 확인하지만, 비교 근거 부족으로 표시하며 KCS 부재나 삭제 가능으로 단정하지 않습니다.

화면에는 완료 건수, 일시정지, 미완료 재시도가 표시됩니다. 작업과 결과는 서버 영구 저장소에 기록되며 창을 닫아도 진행됩니다. 한 문서씩 순차 처리하고 저장된 결과를 재사용합니다. 실패하면 자동 반복 호출 없이 해당 문서를 중단하며, 재시도는 완료된 구간을 건너뜁니다. 서버가 요청 결과를 저장하기 전에 강제 종료된 경우 해당 미완료 요청은 재시작 시 다시 호출될 수 있습니다. API 사용료가 발생하며, GPT 결과는 기존 담당자 판정·메모·선택 근거를 변경하지 않습니다. 백업 복원은 진행 중인 상세비교가 완료되거나 일시정지된 후 실행하세요.

## 업무 흐름

1. `KCS 갱신`으로 국가건설기준센터의 현행 코드 목록과 변경 문서만 내려받습니다. 앱은 코드·버전·갱신일·문서명·상위 분류를 해시한 KCS 개정 식별값과 원문 전체의 무결성 값을 저장합니다. 응답 코드가 요청 코드와 다르거나 본문이 제공되지 않은 문서는 검색에서 격리하고 화면에 제외 건수를 표시합니다. 식별값이 달라지면 기존 프로젝트는 `재업로드·재매칭 필요` 상태가 되어 최종 DOCX가 자동 차단됩니다.
2. 검토할 포스코 시방서 `.doc` 또는 `.docx` 파일을 업로드합니다.
3. 앱이 문단과 표 행을 검토 조항으로 나누고 TF-IDF + BM25로 KCS 후보를 찾습니다. 추정 공종 범위의 결과가 약하면 전체 KCS에서 후보를 보강하고, OpenAI 키가 있으면 임베딩으로 후보 순서를 한 번 더 보정합니다.
   업로드 직후 추출 조항, 후보 제시율, 관련성 높은 후보, 후보 없음, 표 추출 건수를 확인합니다.
4. 후보 점수가 25% 미만이면 원칙적으로 매칭으로 제시하지 않습니다. 단, 포스코 원문에 KCS 코드가 명시된 경우에는 확인용 후보로 표시하며, 한 조항에는 최대 3개 후보만 표시합니다.
5. 문단 경계가 잘못 잡힌 경우 판정 전에 `나누기` 또는 `다음과 합치기`로 보정합니다. 앱은 원문 글자의 임의 수정·누락을 막고, 같은 최신 KCS 개정으로 영향 조항만 다시 매칭합니다. 판정·후보선택 이력이 있거나 품질평가가 시작된 프로젝트에서는 구조 변경을 차단합니다.
6. 담당자가 좌측 사내 조항과 우측 KCS 후보를 비교해 판단합니다. `GPT 정밀분석`은 후보 하나의 관계를 확인하고, `GPT 요구사항 전체포괄 검사`는 포스코 원문을 고정 구간(S1, S2…)으로 나눈 뒤 최대 3개 후보를 조합해 재료·수치·조건·예외·시험 빈도·책임·의무를 구간별로 대조합니다. 긴 포스코 조항과 KCS 후보는 분석용 가상 청크로 내용 누락 없이 자동 분할하며, 모든 호출이 성공한 경우에만 전역 S# 순서로 결과를 보수적으로 통합해 한 번 저장합니다. 한 S# 안의 복합 요구 중 일부만 KCS에 있으면 해당 KCS 근거를 유지한 `부분 포괄`로 판정하고 나머지를 포스코 잔여 문구로 제안합니다. 모든 원문 구간이 정확히 한 번씩 판정되지 않거나 분석 중 원문·후보 내용이 바뀌면 결과를 거부하며, 화면에는 GPT 요약문이 아닌 포스코 원문을 그대로 표시합니다. GPT가 85% 이상 신뢰도로 무관하다고 판정한 미선택 후보만 목록에서 제외되며, `GPT 제외 후보`에서 복원할 수 있습니다.
7. 판정 사유를 선택합니다. `삭제`는 KCS 후보를 근거로 선택하고 포스코 요구사항 전체가 포함되며 수치·조건·예외 차이가 없음을 담당자가 확인해야 저장됩니다. 후보를 재분석하거나 복원하면 기존 전체포괄 판정과 삭제 확인은 자동으로 무효화되므로 다시 검사해야 합니다.
8. 필요한 경우 최종 반영 문구를 수정하고 검토 메모를 남깁니다.
9. 미검토·보류·삭제 근거 미충족 조항이 모두 없어지면 작성자가 검토본을 제출합니다. 제출 시점의 포스코 조항, 판정, 선택 KCS, GPT 분석과 KCS 개정을 하나의 검토 스냅샷과 SHA-256 지문으로 고정하며 프로젝트는 읽기 전용이 됩니다.
10. 승인자는 제출본을 승인하거나 사유와 함께 반려합니다. 반려된 프로젝트만 다시 수정·재제출할 수 있으며, 승인자는 작성자와 다른 이름을 입력해야 합니다. 승인 후에는 승인된 검토본의 지문과 최신 KCS 상태가 모두 일치할 때만 최종 DOCX를 내려받을 수 있습니다.
11. 상단 `데이터 백업`에서 현재 검토 데이터와 참조 중인 원본 DOC/DOCX를 ZIP으로 보관하거나 이전 시점으로 복구합니다. 복구 전에는 현재 상태를 자동으로 한 번 더 백업합니다. 외부 ZIP은 먼저 내용을 검사해 생성 시각과 프로젝트·원본 수를 보여주며, 로컬 서명·파일 해시·SQLite 무결성·표준 스키마·승인 제출본 지문을 모두 통과한 경우에만 적용합니다.

상단 `50개 표본 품질평가`는 업무 판정과 별도입니다. 고유사도 12개, 검토필요 23개, 후보없음 15개를 목표로 문서 전반에서 고정 표본을 만들고 담당자 정답으로 Recall@3, MRR, 정확도를 계산합니다. 해당 구간의 조항이 부족하면 나머지 구간에서 채우며, 전체 평가 가능 조항이 50개보다 적으면 실제 조항 수만 사용합니다. 표본이 생성된 조항은 평가 재현성을 위해 후보 제외·복원 기능이 잠깁니다. 평가 화면은 오류 유형과 점수 구간별 현황을 함께 보여주며, 판정이 쌓이기 전에는 임계값 변경 같은 결론을 만들지 않습니다.

판단 규칙은 다음과 같습니다.

- `남김`: 회사 고유·강화 기준, 대응 KCS가 없는 기준 또는 중복 부분을 제거한 뒤 남길 잔여 기준입니다.
- `삭제`: 선택한 KCS가 포스코 요구사항 전체를 포함하고 차이가 없다고 확인된 조항입니다.
- `보류`: 추가 협의가 필요하며 검토본에는 남지만 확정본에는 포함되지 않습니다.
- 목차와 구조 제목은 판정하지 않고 하위 조항의 KCS 검색 문맥으로만 사용합니다.

## 결과물

- `검토본 DOCX`: 남김과 보류 조항을 포함하고 판단 상태를 표시합니다.
- `확정본 DOCX`: 모든 안전 조건과 작성자–승인자 절차를 통과한 뒤 남김 조항만 포함합니다. 내부 KCS 연결정보와 검토 메모는 제외합니다.
- `감사 이력 XLSX`: 원문, 선택한 KCS 후보, 점수, GPT 관계·근거·간소화 제안, 담당자 판단, 수정문, 메모, 변경 시각을 기록합니다. 삭제 판정 당시의 복수 KCS 전체포괄 결과와 요구사항별 근거도 불변 스냅샷으로 보존하므로 이후 재분석 결과에 의해 과거 이력이 바뀌지 않습니다. 별도 `승인이력` 시트에는 검토 회차, 제출·승인·반려·무효화 처리자와 사유, 시각, KCS 개정 및 검토본 지문을 기록합니다.
- `품질평가 XLSX`: 평가 지표, 코호트·점수 구간별 결과, 오류 신호와 50개 표본의 후보 1~3위를 기록합니다.

원본 DOCX와 검토 상태는 `data` 폴더의 로컬 SQLite 데이터베이스에 저장됩니다. API 응답에는 PC의 로컬 파일 경로나 문서 해시를 노출하지 않습니다.

백업은 기본적으로 `data/backups`에 최근 20개가 저장됩니다. 보관 개수는 `.env`의 `SPEC_MANAGER_BACKUP_RETENTION`으로 1~200개 범위에서 조정할 수 있습니다. 백업에는 SQLite 데이터베이스, 데이터베이스가 참조하는 업로드 원본, KCS 목록 메타데이터만 포함됩니다. `.env`, API 키, KCS 원문 다운로드 폴더와 재생성 가능한 출력 파일은 포함하지 않으므로 KCS 원문은 필요할 때 `KCS 갱신`으로 다시 받을 수 있습니다.

백업 위·변조를 확인하는 비밀키는 ZIP 밖의 `data/.secrets/backup-hmac-v1.key`에 따로 보관됩니다. 내려받은 ZIP을 같은 데이터 폴더에서 다시 올리면 자동 검증됩니다. PC 교체·고장까지 대비하려면 중요한 ZIP과 이 키를 회사가 허용한 별도 보안 저장소에 서로 구분해 보관해야 하며, 키는 일반 사용자에게 배포하지 마세요. 기존 서명 백업이 있는데 키가 사라지거나 손상되면 프로그램은 새 키를 임의로 만들어 과거 백업을 무효화하지 않고 복구·새 백업을 차단합니다.

## 현재 구현 범위

- 프로젝트 목록은 서버 검색·상태 필터와 커서 페이지네이션으로 불러옵니다. `승인 대기`와 `수정 요청` 작업함에서 처리할 문서만 바로 모아볼 수 있습니다. 기존 지붕·철골 문서는 고정 기준 데이터가 아니며, 이후 업로드하는 100개 이상의 시방서도 각각 독립 프로젝트로 저장·검토됩니다.
- `.docx`와 과거 `.doc` 파일을 지원합니다. `.doc`는 설치된 Microsoft Word를 이용해 PC 안에서 `.docx`로 변환한 뒤 분석하며 원본도 보존합니다.
- 일반 문단과 표는 처리하지만, 표는 행 단위 검토 조항으로 변환됩니다.
- 이미지, 텍스트 상자, 복잡한 머리글·바닥글과 원본의 정교한 서식은 그대로 재현하지 않습니다.
- 출력 DOCX는 검토 결과를 기준으로 문서 구조를 다시 구성하므로 원본과 완전히 같은 편집 모양을 보장하지 않습니다.
- 수치·단위, 이상·이하·초과·미만, 금지·의무 표현 차이는 후보 아래 경고로 표시합니다.
- GPT 결과는 담당자 판단을 대신하지 않는 보조 근거이며, 기술적·계약적 최종 판단은 담당자가 확정합니다.
- KCS 갱신 중이거나 원본 JSON이 손상·누락되었거나 manifest·코드 목록·원문 무결성 값이 일치하지 않으면 새 업로드와 최종 출력을 안전하게 차단합니다. 국가건설기준센터가 빈 본문 또는 다른 코드를 반환한 항목은 명시적인 `본문 사용 불가` 레코드로 격리하고 매칭에는 포함하지 않습니다. 같은 KCS 개정에서 완료시각만 바뀐 경우에는 기존 프로젝트를 불필요하게 무효화하지 않습니다.
- 일반 문단은 판정 전에 두 부분으로 나누거나 바로 다음 일반 문단과 합친 뒤 영향 조항만 재매칭할 수 있습니다. 목차·표·기존 판정이력·품질평가 표본과 이전 KCS 프로젝트는 변경할 수 없으며, 변경 전후 내용과 ID는 구조 감사이력으로 보존합니다.
- 긴 포스코 조항은 최대 2,000자 원문 구간과 호출당 8,000자 범위로, 긴 KCS 후보는 8,000자 조각으로 내용 누락 없이 자동 분할합니다. 여러 호출 결과는 최저 신뢰도를 사용하고 충돌·불확실성을 우선하는 삭제 안전 규칙으로 통합합니다. 하나의 장문 의무 또는 KCS 후보가 여러 입력 묶음에 걸리면 조각별 결과가 모두 포괄이어도 `불확실`로 강등해 담당자 검토 없이 삭제되지 않게 합니다. 호출 하나라도 실패하거나 분석 중 원문·후보가 바뀌면 기존 결과를 덮어쓰지 않습니다. 비정상적으로 큰 단일 조항은 비용 보호를 위해 최대 64회 호출에서 중단합니다.
- 작성자 판정과 승인자 확정을 분리하는 2단계 워크플로를 지원합니다. `작성 중 → 승인 대기 → 승인 완료` 또는 `승인 대기 → 반려·수정 중 → 재제출`로 진행되며, 승인 대기와 승인 완료 상태에서는 판정·구조 편집·GPT 분석을 잠급니다. 이 로컬 버전의 이름 입력은 업무 이력용 표시명이며 실제 사내 계정 인증은 아니므로, 운영 배포 시에는 포스코 SSO/권한 체계를 연결해야 합니다.
- 데이터 백업은 WAL 모드의 미반영 데이터를 포함하는 SQLite 일관 스냅샷을 현재 버전의 표준 DB 구조로 다시 구성해 생성합니다. 복구 중에는 상태 변경 요청과 DB 접근을 잠그고, 현행 KCS 개정을 복구본에 먼저 반영한 뒤 검증된 데이터베이스를 원자적으로 교체합니다. 새 데이터베이스 초기화가 실패하면 기존 데이터베이스로 되돌립니다.

## 24시간 상시 운영

화면은 Sites의 공개 주소에서 서비스하고, Python API는 `Dockerfile`로 빌드되는 상시 실행형 클라우드 서비스에 배포합니다. 백엔드에는 반드시 `/var/data` 영구 볼륨을 연결해야 합니다. 볼륨 없이 배포하면 재배포 때 SQLite 데이터베이스, 업로드 문서와 KCS 자료가 사라질 수 있습니다.

백엔드 환경 변수는 다음과 같이 설정합니다. 실제 인증키는 GitHub이나 Docker 이미지에 넣지 않고 호스팅 서비스의 비밀 변수로 등록합니다.

```text
SPEC_MANAGER_DATA_DIR=/var/data/spec-manager
KCS_DATA_DIR=/var/data/kcs
SPEC_MANAGER_CORS_ORIGINS=https://posco-spec-manager.yeongrangrang.chatgpt.site
KCSC_API_KEY=...
OPENAI_API_KEY=...
```

배포 후 `/api/health`가 `200`을 반환하는지 확인하고, 생성된 API 주소를 프런트 빌드의 `NEXT_PUBLIC_API_BASE_URL`에 설정한 뒤 Sites를 다시 배포합니다. 데이터 일관성을 위해 영구 볼륨을 사용하는 백엔드는 한 인스턴스·한 Uvicorn 프로세스로 운영합니다. Docker 환경에서는 LibreOffice가 기존 `.doc` 파일을 `.docx`로 변환합니다.
