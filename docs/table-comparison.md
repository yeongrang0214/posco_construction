# 표 행 비교

## 처리 범위

- Word 본문 표와 텍스트 상자 안의 표를 읽는다. 원본 파일은 수정하지 않는다.
- 가로 병합은 같은 XML 셀만 중복 제거하며, 세로 병합 값은 각 행에 이어 붙인다.
- 표 머리글은 문맥으로 남기고 독립 매칭·판정 대상에서 제외한다.
- 가장 가까운 표 제목의 KS 번호와 현재 행의 강종을 연결한다. 다른 소제목을 넘어 KS 번호를 상속하지 않는다.
- KS 번호와 강종 기호가 같은 KCS 표 행을 검색 후보에 우선 추가한다. 이 경로는 임베딩 유사도나 전체 포괄 판정이 아니며, 검색 점수를 생성하지 않는다.

## 비교 화면

`GET /api/projects/{project_id}/clauses/{clause_id}/table-comparison`

- KCS 근거와 KDS 설계 참고를 구분하고 합계 최대 3개를 표시한다.
- KS·강종 목록 대응과 두께·제품·적용 조건 확인을 분리한다. 현재 조건 비교는 보수적으로 미확인으로 표시한다.
- KDS 원문은 KCSC의 현재 CodeList 개정 정보와 CodeViewer 응답을 대조한다. 성공한 조회는 하루, 실패는 1분 캐시한다.
- KDS 검색 범위는 우선 건축 강구조의 KDS 41 30 10이다. 다른 분야까지 검색했다고 표시하지 않는다.
- KDS는 선택 가능한 KCS 삭제 근거에 섞이지 않는다. 담당자 의견에 의한 삭제는 기존과 같이 가능하다.
- 저장된 후보의 코드·표·개정·본문이 현재 근거와 모두 같아야 선택 버튼을 연결한다.
- 조회 실패는 기준 없음과 구분하고 기존 검색 후보 화면을 유지한다.

## 원문 표시

PDF는 표시용이고 매칭은 Word 추출 텍스트로 수행한다. PDF의 실제 강종 셀 위치와 표 경계를 사용해 행 전체를 강조한다. 위치를 확인할 수 없으면 임의의 행을 강조하지 않고 기존 텍스트 보기를 이용한다.

## 기존 데이터

이 변경은 기존 프로젝트의 조항과 검토 판정을 재작성하지 않는다. 누락된 텍스트 상자 표를 포함하려면 원본을 새로 분석한 프로젝트가 필요하다. KCS 재매칭만으로는 원본의 누락 조항이 추가되지 않는다.

개발 검증 사본은 `scripts/verify_table_preview.py`가 지정된 격리 디렉터리에만 만든다. 원본·기존 검토·공개 서버에는 쓰지 않는다. 이 사본은 표의 규격·강종 직접 대조를 검증하며 전체 문단 재매칭 결과를 뜻하지 않는다.

## 검증

실제 철골 DOC에서 변환한 Word의 표 29개, 검토 가능한 표 행 128개를 추출했다. KS D 3515 표의 11개 행 모두 PDF 7쪽에 연결했다. 회귀 테스트는 병합 셀, 규격 문맥, 강종 접미사, KCS 개정 불일치, KDS 장애, 판정 및 DOCX 내보내기를 포함한다.
